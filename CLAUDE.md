# Digitama — guia para agentes

Pet de área de trabalho (Tauri 2, qualquer PC Windows 10/11) que reage ao Claude Code (hooks) e ao OpenCode (plugin). Visão geral, uso e arquitetura no [README.md](README.md).

A extensão do VS Code (Digimon Pendulum Ver.1.0) mudou para o projeto `C:DEVDevPendulumscode-ext`, fora deste repositório. Para animação de sprites, veja a skill `sprite-motion` (`.claude/skills/`).

## Build e testes
```
npm install
npm run tauri dev              # compila o relay (release) antes
npx tsc --noEmit               # tipos do frontend
cargo test --workspace         # testes do relay e do app
node scripts/preview-sprites.mjs out.png 4   # folha com todos os sprites
```

## Regras
- **Nunca travar o Claude Code**: o relay (`hook/`) sai na hora se o app não responde; só `PermissionRequest` espera, e só depois do ACK do balão.
- **Nunca permitir sem clique**: sem decisão humana, o relay não imprime nada (`hook/src/reply.rs`).
- **Nunca gravar `~/.claude/settings.json` sem prévia**: diff → clique → backup datado → gravação, recusando se o arquivo mudou (`hooks_install.rs`).
- O chat usa o `claude.exe` logado (OAuth) ou o `opencode run` (provedores do próprio OpenCode). Não adicionar chamadas diretas a APIs nem guardar chaves.
- O chat trabalha na pasta do Digitama (`%APPDATA%\…\chat`) ou numa pasta de projeto que **o usuário escolheu** (📁, "＋" no projeto, ou continuar uma sessão do VS Code, que trabalha na pasta dela). Nunca escolher pasta sozinho. Todo `claude.exe` aberto pelo app passa por `claude::clean_env` (sem as variáveis da sessão do VS Code que abriu o `tauri dev`).
- Nada de caminhos fixos desta máquina: executáveis dos agentes são procurados (`find_claude`, `opencode::find_opencode`), dados ficam em %APPDATA%/%LOCALAPPDATA%. O plugin do OpenCode é gerado (`opencode.rs`) e só sobrescreve arquivo com a marca "generated by Digitama".
- Criar janelas (`WebviewWindowBuilder::build`) só em contexto assíncrono: em handler síncrono trava no Windows (`open_window_later`).
- `DisconnectNamedPipe` descarta dados não lidos: responda pelo pipe e use `drain_then_disconnect`.
- Sprites reais (Digimon World DS) vêm de `scripts/fetch-sprites.mjs` para a pasta local do usuário (%APPDATA%), nunca para o repositório; `src/pet/render.ts` remove fundo, recorta, gera silhuetas e o ciclo de passos. `src/pet/sprites.ts` (desenho em código) é só a reserva e os ovos.
- Não automatizar mouse/teclado nem tirar prints da tela inteira do usuário: ele trabalha no ERP com dados de clientes (LGPD). Peça para ele testar.
- Linhas evolutivas escolhidas pelo usuário: Agumon → WarGreymon, Guilmon → Gallantmon, Dorumon → Alphamon. Escolhas criativas (personagens, estilo): pergunte antes.
- Sessões do VS Code no chat (`sessions.rs`): só se lê o começo e o fim dos transcritos em `~/.claude/projects`, nunca se grava neles. "Continuar aqui" passa o chat para a pasta da sessão e retoma com `--fork-session` (sem a pasta, copia o transcrito para a do chat); nunca retome o id original (a extensão está gravando nele). As sessões internas do Digitama (chat, uso) ficam fora da lista.
- Chat com várias conversas (`claude.rs`: `Chats`/`Conv`): cada uma com o seu processo, pasta, permissões e registro; todo evento vai à página com `digitama_conv`. Perguntas (`AskUserQuestion`) chegam como `can_use_tool` e voltam com `allow` + o mesmo input + `answers`.
- Permissões no chat: o `claude.exe` do chat roda com `--permission-prompts host --permission-prompt-tool stdio`; cada `can_use_tool` vira cartão e só segue com o clique (`chat_permission`). Modos permitidos: manual (padrão), auto, acceptEdits, plan — nunca `bypassPermissions`/`dontAsk`. O hook `PermissionRequest` das sessões internas não vai para o balão do pet.
- Textos da interface e comentários em português do Brasil.
